# L2.3 边沿：一个按钮当开关用

> 教练读法：这一课的核心是"电平 vs 边沿"。他写错的第一版一定是"每周期翻转"，让仿真跑起来给他看，比讲原理快。

---

## 0. 这节课要得到什么

一个按钮：按一下启动，再按一下停止。长按只算一次，快速连按三次要能正确响应。

---

## 1. 为什么"电平"不行

新手第一版一般写：

```scl
IF #Btn THEN
    #Run := NOT #Run;      // ← 看起来对，实际错
END_IF;
```

按下去的那几百毫秒里，程序跑了**几百个扫描周期**，每个周期都翻转一次。结果是：灯在狂闪，松手时停在哪全靠运气。

**这不是"偶尔出错"，是必然出错。** 只要条件成立的时间 > 一个扫描周期，电平写法就一定会重复触发。

---

## 2. 正确写法：只认"变化"

```scl
#Trig(CLK := #Btn);                 // 上升沿检测，实例放 Static
IF #Trig.Q THEN
    #Run := NOT #Run;
END_IF;
```

梯形图里就是 `┤P├` 触点：

```text
      Btn(P)                                    Run
──┤P├──┬──────────────────────────────────────( )──
       │
       └─┤ ├──┐   （用 Run 自锁/取反按需组合）
```

`┤P├` 只在 `Btn` **从 0 变 1 的那一个扫描周期**通，所以一次按下只触发一次。

---

## 3. 两个容易踩的点

| 点 | 说明 |
|---|---|
| **实例放哪** | `R_TRIG` 的实例必须放 Static（或背景 DB）。放临时变量里，下次进来是空的，边沿永远检测不到 |
| **被多次调用的块** | 同一个 FB 被调用 3 次，如果边沿实例是**共享的**，只有第一次能触发。每个调用要有自己的实例（多重实例） |

---

## 4. 你要交的东西

| # | 用例 | 期望 | PASS/FAIL |
|---|---|---|---|
| 1 | 按一下松开 | `Run` 变 1，保持 | |
| 2 | 再按一下 | `Run` 变 0 | |
| 3 | 长按 5 秒 | `Run` 只翻转**一次** | |
| 4 | 快速连按三次 | 翻转三次（1→0→1） | |
| 5 | 用监控表把 `Btn` 手动置 1 保持 3 秒 | `Run` 只翻转一次 | |

**判据**：编译 0 错误 0 警告；五条用例全过；能说出"为什么电平写法会狂闪"。

---

## 5. 常见失败与提示

| 现象 | 一级提示 | 二级提示 |
|---|---|---|
| 灯狂闪 | 条件成立的这几百毫秒里，程序跑了几圈？ | 只在"变化"那一刻触发 |
| 第一次能按，第二次不灵 | 边沿实例存在哪个区？ | 放 Static，别用临时变量 |
| 在 FB 里只有第一个调用生效 | 三个调用共用了一个实例吗？ | 用多重实例，每个调用一个 |
| 用 `P` 触点还是 `R_TRIG` 分不清 | 两者都是上升沿，选一个用就行 | LAD 用 `P`，SCL 用 `R_TRIG` |

---

## 6. 为什么

1. **为什么要边沿？** 因为"按下"是一个**事件**，"按住"是一个**状态**。事件只发生一次，状态会持续。
2. **为什么扫描周期会让电平写法出错？** 程序每秒跑几百上千次。人眼觉得"按了一下"，CPU 看到的是"条件成立了 800 次"。
3. **为什么实例要 Static？** 边沿检测要记住"上一次是什么值"。记不住上一次，就判断不了"变了没有"。

---

## 7. 收尾

> **"'按住'是状态，'按下'是事件。开关要的是事件，所以必须用边沿。"**
