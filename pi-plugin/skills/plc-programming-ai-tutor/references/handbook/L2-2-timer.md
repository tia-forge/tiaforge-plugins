# L2.2 定时器：TON 的四个脚

> 教练读法：这一课有一个**真实的高频报错**（`PT` 缺失），大概率会出现。出现了别急着改，先让他读报错原文——读报错是这一课的一半。

---

## 0. 这节课要得到什么

输送机启动后延时 3 秒，再输出"可以进料"。

学完你要能说出：**TON 的 `IN`、`PT`、`Q`、`ET` 各是什么，以及为什么复位时也要给 `PT`。**

---

## 1. TON 四个脚

| 脚 | 含义 | 一句话 |
|---|---|---|
| `IN` | 计时条件 | 它为 1 时开始计时，变 0 立刻清零 |
| `PT` | 预设时间 | 计到它，`Q` 变 1 |
| `Q` | 输出 | 到点了才 1 |
| `ET` | 已计时 | 现在计到哪了（调试时看这个） |

```scl
#Timer_1(IN := #Run, PT := T#3S);
#Ready := #Timer_1.Q;
```

---

## 2. 三个必须知道的规矩

1. **每个扫描周期只调用一次。** 一个定时器在同一周期调两次，第二次会覆盖第一次的结果，时间会乱。
2. **每次调用都要给全参数**，包括 `PT`——**哪怕这次只是把它复位**。
3. **实例要存在能"记住"的地方**：FB 的 Static 区，或一个单独的背景 DB。放在 FC 里存不住（FC 没有静态区）。

---

## 3. 第一次写，多半会这样

```scl
IF #Reset THEN
    #Timer_1(IN := FALSE);      // ← 只给了 IN
    #Ready := FALSE;
END_IF;
```

编译报：

```text
[Error] Parameter 'PT' has to be used.
```

**正确写法**：不要"单独复位"，把复位条件并进 `IN`：

```scl
#Timer_1(IN := #Run AND NOT #Reset, PT := T#3S);
#Ready := #Timer_1.Q AND NOT #Reset;
```

这样每周期只有一次调用，参数永远齐全，复位也生效。

---

## 4. 你要交的东西

| # | 用例 | 期望 | PASS/FAIL |
|---|---|---|---|
| 1 | `Run`=1 持续 2 秒 | `Ready` 仍是 0 | |
| 2 | `Run`=1 持续 3.5 秒 | `Ready` 变 1 | |
| 3 | `Run`=0 | `Ready` 立刻变 0，`ET` 回 0 | |
| 4 | `Run`=1 计时到 2 秒时 `Reset`=1 | `Ready` 保持 0，`ET` 回 0 | |
| 5 | `Reset` 回 0 后 `Run` 仍为 1 | 重新从 0 开始计满 3 秒 | |

**判据**：编译 0 错误 **0 警告**；五条用例全过；能指出代码里计时器**只被调用了一次**（贴出那一行）。

---

## 5. 常见失败与提示

| 现象 | 一级提示 | 二级提示 |
|---|---|---|
| 报 `PT has to be used` | 这次调用给了几个参数？ | 复位那次也要给 `PT` |
| 时间忽长忽短 | 这个计时器在这个周期里被调了几次？ | 合并成一次调用 |
| 复位后不再计时 | `IN` 什么时候能重新变 1？ | 复位条件要"松开" |
| 下载后报实例相关错误 | 实例声明在哪个区？ | 放 Static 区，或建背景 DB |
| 到点了但输出不亮 | 输出是接 `Q` 还是接 `IN`？ | 用 `.Q` |

---

## 6. 为什么

1. **为什么"复位也要给 PT"？** 因为那不是"复位函数"，那是一次完整调用——`IN := FALSE` 只是让它清零，但调用本身仍需要所有参数。
2. **为什么只调一次？** 定时器内部有状态（已计时间）。一周期调两次，第二次拿到的状态是第一次刚改过的，等于自己踩自己。
3. **`ET` 有什么用？** 调试和"进度指示"（比如 HMI 上显示还要多久）。生产逻辑里判"到没到"永远用 `Q`，不用 `ET` 比较。
