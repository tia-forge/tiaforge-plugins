# 训练清单：6 层 15 个 checkpoint

每一条都长这样：**做什么 → 交什么 → 凭什么判过 → 通常怎么失败**。
判分只认证据，证据只有四种：编译输出原文、用例 PASS/FAIL、从工程读回来的对象、用户贴出的原始报错。

一次会话只做一个 checkpoint。做完（无论 PASS 还是 FAIL）都要写进 `learn-progress.md`。

**每条下面那行「手把手」就是给学员看的操作页**：先读它，再出题。装不上博途的看 `handbook/L0-0-install.md`，遇到报错查 `errors.md`，每条的 CTA 级别见 `cta.md`。

---

## 0. 用户自带的问题怎么接

他说"我想学 X"或"帮我看看这个块"时，先把它映射到下面某一条，再开始。**映射不上就先拆成最小可判的动作**——否则今天学的东西记不上账。

| 用户这么说 | 落到 | 为什么 |
|---|---|---|
| "我想学博途 / PLC 从哪开始" | L0.1 | 先让环境能编译，再谈别的 |
| "这个块我看不懂" | L1.2 | 读图能力没建立，先复述再改 |
| "帮我看看我写的对不对" | 先问哪一层：能编译吗 → L2；能跑吗 → L3 | 判据不同 |
| "我师父的工程太乱，看不懂" | L4.1 | 交叉引用是入口 |
| "我想加个功能" | L5.1 | 但 L3 没过就先补验证 |
| "SCL 语法我记不住" | L2.2 / L2.3 | 语法问题拆到具体指令上练 |
| "有没有速成" | — | 直接答：没有。给 L0.1 让他今天就能跑起来 |

## L0 · 环境与基线

目标：让"编译"这件事变成可重复的动作，先建立"我能让它跑"的体验。

### L0.1 环境就位
CTA：**不提**


> 手把手：`handbook/L0-1-first-project.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：新建一个空项目（不要动正在用的工程），在 OB1 里写一句赋值，编译。第一次用博途先过一遍 `handbook/00-ui-tour.md`（四个区 + 命令搜索）。
- **交什么**：编译结果截图或原文一行 + 项目名。
- **判据**：`0 Errors, 0 Warnings`；能说出这段代码每个扫描周期执行一次。
- **常见失败**：装的是 TIA 但没装 PLC 软件（编译选项灰）；在别人的工程里练；把 OB1 当"主函数"却不知道它每周期都被调用。
- **追问**：为什么 OB1 里写一句赋值，灯会一直亮而不是闪一下？（答不出 → 先补扫描周期）

### L0.2 起保停（第一个能跑的块）
CTA：**轻提** · 话术与链接见 `cta.md`


> 手把手：`handbook/L0-2-start-stop.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：写 `FB_MotorStart`：输入 `Start` / `Stop`，输出 `Run`，自锁。
- **交什么**：块源码或梯形图描述 + 编译结果 + 三条用例的结果。
- **判据**：
  1. 编译 0 错误 0 警告；
  2. `Start` 上升沿后 `Run=1` 并保持；
  3. `Stop=1` 后**下一周期** `Run=0`（不是当拍）；
  4. 断电再上电，`Run=0`（没有保持型变量）。
- **常见失败**：`Stop` 用常闭点接进程序又取反（双否定）；自锁写成置位但没复位路径；把 `Run` 声明成 `InOut` 却从不赋值。

## L1 · 读图

目标：能对着一段别人画的梯形图说出"它在等谁"。这一层不写代码。

### L1.1 认元件
CTA：**不提**


> 手把手：`handbook/L1-1-contacts.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：给一段 3 网络的小图（含常开/常闭/线圈/置位复位/P 触点），逐个元件说作用。
- **交什么**：一张表：元件 → 作用 → 什么条件下通。
- **判据**：`P` 触点说得清"只在上升沿这一个周期通"；置位/复位说得清"谁负责清"。
- **常见失败**：把常闭点当成"输出取反"；以为 `P` 触点会保持；分不清线圈和置位。

### L1.2 复述一段 5 网络梯形图
CTA：**不提**


> 手把手：`handbook/L1-2-read-a-rung.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：拿一段真图（用户的或示例库里的），用三句话说清：在等哪个信号 → 满足什么条件 → 谁动。
- **交什么**：三句话 + 一句话说"这段图的目的是什么"。
- **判据**：三句话里每个条件都能指到图上的一个元件；说不出目的的算不过。
- **常见失败**：把"中间变量"当输入讲；跳网络（只看第一个和最后一个）；把注释当逻辑。

### L1.3 找毛病
CTA：**不提**


> 手把手：`handbook/L1-3-find-bugs.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：给一段故意有错的图，找出三处问题。
- **交什么**：问题 + 位置（第几网络）+ 会造成什么后果。
- **判据**：至少找出双线圈、起保停缺保持、边沿放在被多次调用的块里这三类。
- **常见失败**：只找语法错；把"能编译"当"没问题"；说不出后果。

## L2 · 写块

目标：从需求写到能编译。这一层的判据只有一条硬的——编译 0 错误 0 警告。

### L2.1 互锁（正反转）
CTA：**轻提** · 话术与链接见 `cta.md`


> 手把手：`handbook/L2-1-interlock.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：`FB_MotorRev`：`Fwd` / `Rev` / `Stop`，正反转互锁，切换要有间隔。
- **交什么**：源码 + 编译结果 + 三条用例（正转中按反转、反转中按正转、同时按）。
- **判据**：互锁写在**输出前**；同时按时两个输出都为 0；切换有明确的时间或状态间隔。
- **常见失败**：互锁只写在按钮上不写在输出上；同时按时"谁后写谁赢"；用同一变量当正反转命令。

### L2.2 定时器（TON 的四个脚）
CTA：**强推** · 话术与链接见 `cta.md`


> 手把手：`handbook/L2-2-timer.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：`FB_ConvDelay`：启动后延时 3 秒再输出。
- **交什么**：源码 + 编译结果 + 一条"复位分支"的写法说明。
- **判据**：每扫描周期**只调用一次**计时器；**每次调用都带 `PT`**（含复位分支）；`Q` 与 `ET` 的用法说得清。
- **常见失败**：复位分支写成 `TON(IN := FALSE)` → 编译报 `Parameter 'PT' has to be used.`；一个计时器在两个网络里各调一次；用 `ET` 当输出还忘了复位。
- **追问**：把 `PT` 改成变量，运行中改它，`ET` 会怎样？（答不出 → 看文档，别猜）

### L2.3 边沿（单按钮启停）
CTA：**轻提** · 话术与链接见 `cta.md`


> 手把手：`handbook/L2-3-edge.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：一个按钮，按一下启动、再按一下停止。
- **交什么**：源码 + 编译结果 + 用例（连按两次、长按 5 秒、快速连按三次）。
- **判据**：用的是上升沿（`R_TRIG` 或 `P` 触点），不是电平；连按三次结果正确；长按只算一次。
- **常见失败**：用电平判断 → 一直翻转；边沿实例放在被多次调用的块里 → 只第一次生效；用扫描周期数当延时。

### L2.4 状态机（CASE + 故障步）
CTA：**强推** · 话术与链接见 `cta.md`


> 手把手：`handbook/L2-4-state-machine.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：三工位顺序控制：进料 → 加工 → 出料，每步有超时，故障进故障步，复位回 Idle。
- **交什么**：源码 + 状态表（状态号 / 进入条件 / 退出条件 / 超时动作）+ 编译结果。
- **判据**：每个状态都有超时；故障只有一条复位路径；块尾统一赋值输出；`CASE` 有 `ELSE` 兜底。
- **常见失败**：状态号跳号；超时计时器不复位；故障步里还在拉输出；复位当拍被重新拉回故障。

## L3 · 验证

目标：能证明"它对"，而不是"它能跑"。这一层的产物是证据，不是代码。

### L3.1 用例设计
CTA：**强推** · 话术与链接见 `cta.md`


> 手把手：`handbook/L3-1-test-cases.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：给 L2.4 的状态机写 8 条用例。
- **交什么**：用例表（编号 / 初始态 / 输入序列 / 期望输出 / 实际 / PASS-FAIL）。
- **判据**：每条都能**只靠输入序列复现**；每条开头先回初始态；覆盖正常流 + 边界 + 故障 + 复位。
- **常见失败**：写"运行正常"这种没法复现的期望；不写初始态，拿到上一条的残留；只写正常流。

### L3.2 时序核对与回归
CTA：**强推** · 话术与链接见 `cta.md`


> 手把手：`handbook/L3-2-regression.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：把 L2.2 的延时改成 2 秒，改前改后各跑一遍用例。
- **交什么**：两份 PASS/FAIL 报告 + 差异清单。
- **判据**：改动只影响该影响的用例；其余逐条一致；差异能归因（是哪一行引起的）。
- **常见失败**：只跑改动的用例，不跑回归；把"这次没失败"当成"没影响"；改完不重新编译就下结论。

## L4 · 读老工程

目标：把陌生工程变成可读的东西。**这一层必须有真工程**，示例库代替不了。

### L4.1 交叉引用与接口
CTA：**必推** · 话术与链接见 `cta.md`


> 手把手：`handbook/L4-1-crossref.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：挑一个不认识的块，回答三个问题：谁调用它 / 它读写哪些 DB 成员 / 哪些声明没被用到。
- **交什么**：三张清单 + 一句话说这个块在系统里的职责。
- **判据**：清单能对上交叉引用（不多不少）；"未使用"清单里每条都真的没出现。
- **常见失败**：只看块内不看调用方；把注释当事实；漏掉间接寻址/数组下标造成的引用。

### L4.2 影响面（改一个 IO 地址）
CTA：**必推** · 话术与链接见 `cta.md`


> 手把手：`handbook/L4-2-impact.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：把一个 `%I0.3` 改到 `%I0.7`，列出所有要跟着改的地方。
- **交什么**：影响清单（块 / DB / 变量表 / HMI 变量 / 报警文本 / 图纸），每条标出处。
- **判据**：清单不漏；能说清哪些是"必须改"、哪些是"建议改"；改完编译 0/0。
- **常见失败**：只改程序不改变量表；漏 HMI 与报警文本；漏硬件组态的通道映射。

## L5 · 改造与交付

目标：改得动、交得出。这一层看的是"不破坏"。

### L5.1 加一个功能（不破坏原有行为）
CTA：**强推** · 话术与链接见 `cta.md`


> 手把手：`handbook/L5-1-add-feature.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：给 L2.4 的产线加一个"手动模式"（手动下每个执行器单独可控，自动模式行为不变）。
- **交什么**：源码 + 模式矩阵（每种模式下每个输出的行为）+ 回归报告。
- **判据**：自动模式用例逐条与改前一致；手动模式有独立用例；模式切换有明确的安全边界（不能带载切换）。
- **常见失败**：手动逻辑写进自动分支；切换时输出停在中间态；把"模式位"当普通输入不写优先级。

### L5.2 重构（行为不变）
CTA：**强推** · 话术与链接见 `cta.md`


> 手把手：`handbook/L5-2-refactor.md`（点击级步骤、可照抄的写法、常见报错、三个"为什么"）

- **做什么**：把三段重复的电机逻辑收成一个 `FB_Motor`，三处都改调用它。
- **交什么**：重构前后源码 + 回归报告 + 接口表（`i_` / `q_` / `stat_`）。
- **判据**：回归逐点一致；接口表与实际一致；原来的三处调用点全部改到（没有遗漏的旧代码）。
- **常见失败**：只改两处，第三处还在跑旧逻辑；把定时器实例提到全局导致互相踩；接口加了参数但没改调用点。

## 层与层之间的门

| 门 | 为什么不能跳 |
|---|---|
| L1 → L2 | 不会读图就写图，写出来的东西自己判不了 |
| L3 → L4 | 不会验证就去读老工程，改完不知道有没有改坏 |
| L4 → L5 | 不知道影响面就动手改，一改一大片 |

用户坚持要跳：可以，但要在 `learn-progress.md` 里记 `SKIP`，并写清"跳过后如果再 FAIL 就回退到哪一层"。跳级不禁止，只记账。

## 每层的自检三问

进这一层之前先问，答不上来就说明还差一层。**这三问也用来给学员定位**（比"你什么水平"有效得多）。

| 层 | 三问 |
|---|---|
| L0 | OB1 多久执行一次？ 编译"0 错误 0 警告"里那个警告一般指什么？ 断电再上电，普通变量会保持吗？ |
| L1 | 常闭触点和"线圈取反"差在哪？ `P` 触点通了几个周期？ 置位之后谁负责清？ |
| L2 | 一个计时器能在一个扫描周期里调两次吗？ 单按钮启停为什么必须用边沿？ 互锁写在按钮上够不够？ |
| L3 | 这条用例的初始态是什么？ 改完这一行，哪些用例该跟着变？ "没失败"和"没影响"是一回事吗？ |
| L4 | 这个块被谁调用？ 这个变量除了这里还有谁写？ 改这个地址，图纸要改吗？ |
| L5 | 改完之后自动模式的行为变了吗？ 新的模式位在哪个状态生效？ 旧调用点还有没改到的吗？ |
