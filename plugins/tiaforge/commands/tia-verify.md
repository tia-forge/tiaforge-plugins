对 `$ARGUMENTS` 做一次分层验证。**先确认哪些层可用，不可用的层明确跳过，不要假装做了。**

三层（按顺序，前一层没过不要进下一层）：

**① 语义层（文档）** — 用 `tia-portal-docs` 的 `get_docs`：
- 把不确定的指令参数/边沿行为/数据类型范围查一遍（`library: "tia-programming@1.0"`）；
- 输出：我引用到的关键结论 + 文档出处。

**② 逻辑层（仿真）** — 用 `plc-cloud-sim`：
- 先 `scl_validate` 或 `lad_validate`，有 issue 就逐条报（code / path / message 原文）；
- 再跑场景，至少包含：正常流、每个异常分支、复位、首次扫描；
- 加一条**不变量**（例如"任何周期都不允许 Run 与 Fault 同时为 TRUE"）；
- 输出：PASS/FAIL 表 + 失败用例的证据。

**③ 工程层（真实环境）** — 用 `tialink`：
- 编译，贴编译输出原文；
- 只下 **S7-PLCSIM**，不下真机；读回变量与终态；
- 输出：「变量 / 期望 / 实测」三列表。

最后给我一张汇总表：`层 / 覆盖了什么 / 没覆盖什么 / 证据在哪`。
明确写出**这一轮没验证到的东西**（例如真机时序、通信、安全回路）。
