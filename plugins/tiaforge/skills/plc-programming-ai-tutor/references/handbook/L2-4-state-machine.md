# L2.4 状态机：三个工位，一条顺序

> 教练读法：这一课开始"像真的了"。**先让他画状态表，再让他写代码**——顺序反了，写出来一定是一堆 IF 套 IF。

---

## 0. 这节课要得到什么

进料 → 加工 → 出料，三步按顺序走，每步都有超时，出错进故障步，按复位回初始。

---

## 1. 先画状态表（不许跳过）

| 状态 | 名字 | 进入条件 | 做什么 | 退出条件 | 超时 |
|---|---|---|---|---|---|
| 0 | Idle | 上电 / 复位 | 全部输出 0 | `Start` 上升沿 | — |
| 10 | Feed | 从 0 进 | `Conv=1` | `PartAt=1` | 5 秒 → 故障 90 |
| 20 | Process | 从 10 进 | `Proc=1` | `ProcDone=1` | 10 秒 → 故障 90 |
| 30 | Discharge | 从 20 进 | `Out=1` | `PartGone=1` | 5 秒 → 故障 90 |
| 90 | Fault | 任一超时 | 全部输出 0，`FaultCode`=来源状态 | `Reset` 上升沿 → 0 | — |

**判据之一**：这张表的每一行，"退出条件"都能指到一个真实信号。

---

## 2. 代码骨架（照这个结构写，别自己发明）

```scl
// 1) 状态迁移：只改状态，不碰输出
CASE #State OF
    0:
        IF #StartEdge THEN #State := 10; END_IF;
    10:
        IF #PartAt THEN
            #State := 20;
        ELSIF #T_Step.Q THEN
            #FaultCode := 10; #State := 90;
        END_IF;
    20:
        IF #ProcDone THEN
            #State := 30;
        ELSIF #T_Step.Q THEN
            #FaultCode := 20; #State := 90;
        END_IF;
    30:
        IF #PartGone THEN
            #State := 0;
        ELSIF #T_Step.Q THEN
            #FaultCode := 30; #State := 90;
        END_IF;
    90:
        IF #ResetEdge THEN #FaultCode := 0; #State := 0; END_IF;
    ELSE
        #State := 90; #FaultCode := 999;      // 兜底：不认识的状态一律进故障
END_CASE;

// 2) 一步超时：用当前状态决定计时条件
#T_Step(IN := (#State = 10) OR (#State = 20) OR (#State = 30),
        PT := T#5S);                          // 不同步长不同？见下面"进阶"

// 3) 输出：块尾统一赋值，无条件
#Conv    := (#State = 10);
#Proc    := (#State = 20);
#Out     := (#State = 30);
#Running := (#State <> 0) AND (#State <> 90);
```

三条硬规矩：

1. **迁移段只改状态**，不要在 `CASE` 里写输出。
2. **输出段无条件赋值**——每个输出在每一轮都有确定的值（这就是 `might not be initialized` 警告的解法）。
3. **故障只有一个出口**（都进 90），**复位只有一条路径**（90 → 0）。

---

## 3. 进阶：每步超时不一样

上面的写法共用一个 5 秒。要每步不同，就三个定时器，各自的条件写各自的：

```scl
#T_Feed(IN := (#State = 10), PT := T#5S);
#T_Proc(IN := (#State = 20), PT := T#10S);
#T_Out (IN := (#State = 30), PT := T#5S);
```

**别用一个定时器改 `PT` 来实现"不同步长"**——改 `PT` 的时机和计时器内部状态会打架。

- 四条用例全过；
- 代码里 `CASE` 有 `ELSE` 兜底；
- 输出段在 `CASE` 之外，且无条件赋值。

## 5. 常见失败与提示

| 现象 | 一级提示 | 二级提示 |
|---|---|---|
| 一堆 IF 套 IF | 你现在有几个"阶段"？ | 用状态号表示，`CASE` 分派 |
| 故障后复位不了 | 复位是从哪个状态出去的？ | 只有 90 能回 0 |
| 复位当拍又进故障 | 复位那一刻超时信号还在吗？ | 复位时先清故障码和定时器 |
| 输出在故障态还在动 | 输出是写在 `CASE` 里的吗？ | 挪到块尾，按状态无条件赋值 |
| 编译报"可能未初始化" | 哪个输出不是每轮都有值？ | 块尾统一赋值 |
| 走完一圈回不到 Idle | 30 的退出条件指到哪？ | 指到"料已离开"的信号 |

---

## 6. 为什么

1. **为什么用状态号而不是一堆布尔？** 布尔多起来会出"两个都真"的组合。状态号天然互斥。
2. **为什么输出要在块尾统一赋值？** 让每个输出的值只由"当前状态"决定，不受执行顺序影响。**这是可验证性的基础。**
3. **为什么要 `ELSE` 兜底？** 状态号可能被外部改坏（HMI、通信、保持性变量）。兜底让它进故障，而不是"什么也不做"。
