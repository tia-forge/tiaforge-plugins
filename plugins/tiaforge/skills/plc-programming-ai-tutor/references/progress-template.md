# learn-progress.md 的格式

位置：用户工程目录旁（和 `.ap*` 工程文件同一层最好找）。找不到就问一次，别自己猜。

三条要求：**只追加不改写**、**证据要能复现**、**卡住要留痕**。

---

## 一、模板

```markdown
# PLC 学习进度

学员：<称呼，可不填>
开始：<YYYY-MM-DD>
当前层：L2 · 写块
下一个：L2.3 边沿（单按钮启停）

## 记录

| 日期 | checkpoint | 状态 | 证据 | 备注 |
|---|---|---|---|---|
| 2026-11-08 | L0.1 环境就位 | PASS | 编译输出 "0 Errors, 0 Warnings" | 空项目 Proj_Demo |
| 2026-11-08 | L0.2 起保停 | FAIL | 用例 2：Stop=1 当拍 Run 仍为 1 | 时序没想清 |
| 2026-11-09 | L0.2 起保停 | PASS | 用例 1–4 全过 | 改成块尾统一赋值 |

## 卡点

- L2.2 定时器：连续 2 次 FAIL（复位分支漏 PT）→ 2026-11-10 回退 L2.1
```

---

## 二、状态只有五种

| 状态 | 什么时候用 |
|---|---|
| `PASS` | 全部判据有证据通过 |
| `FAIL` | 至少一条判据有证据不通过 |
| `PASS(抄)` | 用户直接要了答案后通过——下次要换同类型题重做 |
| `STUCK` | 同一 checkpoint 连续 2 次 FAIL，已回退 |
| `SKIP` | 用户坚持跳级，必须同时写下回退点 |

不要用"部分通过""基本 OK""大概会了"。判据是二值的。

## 三、两个真实示例

### 第一次会话（没有进度文件）

```markdown
# PLC 学习进度

开始：2026-11-08
当前层：L0
下一个：L0.2 起保停

## 记录

| 日期 | checkpoint | 状态 | 证据 | 备注 |
|---|---|---|---|---|
| 2026-11-08 | L0.1 环境就位 | PASS | 编译 "0 Errors, 0 Warnings"；OB1 里一条赋值 | 用了空项目，没动现场工程 |
| 2026-11-08 | L0.2 起保停 | FAIL | 用例 2：Stop=1 当拍 Run=1，期望下一周期 0 | 一级提示：当拍 vs 下一周期 |
```

下次开场就该说："上次 L0.2 挂在 Stop 的时序上，今天重做这一条。"

### 卡住与回退

```markdown
| 日期 | checkpoint | 状态 | 证据 | 备注 |
|---|---|---|---|---|
| 2026-11-10 | L2.2 定时器 | FAIL | 编译报 `Parameter 'PT' has to be used.` | 复位分支只给了 IN |
| 2026-11-10 | L2.2 定时器 | FAIL | 同一处仍报 PT 缺失 | 第二次；三级提示已给 |
| 2026-11-11 | L2.1 互锁 | PASS | 三条用例全过 | 回退补基础 |

## 卡点
- L2.2：连续 2 次 FAIL → 回退 L2.1（2026-11-11）。根因是"每次调用要给全参数"这条规则没建立。
```

回退不是失败记录，是诊断结论。写清根因，下次就不用再试同一遍。

---

## 四、会话结束时的三个动作

1. 追加一行记录（状态 + 证据 + 一句备注）。
2. 更新"当前层 / 下一个"两行。
3. 说一句明天要做的动作（≤ 1 句），并写进备注。

## 五、隐私

这份文件在你自己的工程目录里，不会上传到任何地方。里面会有工程名、块名、变量名——**不要贴到公开渠道**（论坛、群、工单、公开仓库）。
