# L5.1 加功能：手动模式，且不弄坏自动

> 教练读法：这一课的判据是"自动模式一条都不能变"。他会觉得"我加的是新东西"，所以要让他自己跑回归——用结果说服他。

---

## 0. 这节课要得到什么

给 L2.4 的产线加一个**手动模式**：手动下每个执行器能单独开停；自动模式的行为**一点都不能变**。

---

## 1. 先定模式矩阵（这张表是核心交付物）

| 输出 | 自动 | 手动 | 维护 / 空跑 |
|---|---|---|---|
| `Conv` | 按状态机 | 手动开关 | 0 |
| `Proc` | 按状态机 | 手动开关 | 0 |
| `Out` | 按状态机 | 手动开关 | 0 |
| `Running` | 状态 ≠ 0/90 | 手动开关 | 0 |

**判据**：每一格都有明确的值，没有空格。空格就是"到时候看情况"，现场就会出情况。

---

## 2. 三条硬规矩

1. **模式判断写在输出段**，不要在每个状态里加 `IF 手动`。
2. **手动下状态机照常跑但不输出**（或冻结，二选一，写清楚）。
3. **切换要有边界**：带载切换必须禁止——比如气缸伸出中不能切模式。

```scl
// 状态机照常迁移（自动逻辑不动）
CASE #State OF ... END_CASE;

// 输出段：按模式分派
IF #Mode = 1 THEN                      // 手动
    #Conv := #ManConv; #Proc := #ManProc; #Out := #ManOut;
ELSE                                   // 自动（原逻辑，一个字都没改）
    #Conv := (#State = 10); #Proc := (#State = 20); #Out := (#State = 30);
END_IF;
```

---

## 3. 你要交的东西

| # | 交什么 | 判据 |
|---|---|---|
| 1 | 模式矩阵 | 无空格 |
| 2 | 自动模式回归报告 | 与改前**逐条一致** |
| 3 | 手动模式用例（4 条） | 每个执行器单独可控 |
| 4 | 切换边界说明 | 说清"什么条件下不许切" |

---

## 4. 常见失败与提示

| 现象 | 一级提示 | 二级提示 |
|---|---|---|
| 自动模式用例挂了一条 | 你改了哪一行？ | 模式判断是不是插进了 `CASE` 里 |
| 手动下状态机还在走 | 手动时状态该冻还是该继续？ | 先定规则，再写代码 |
| 切换瞬间输出乱跳 | 切换那一个周期，输出是谁赋的值？ | 输出段只能有一个入口 |
| 手动的按钮不受控 | 手动信号经过互锁了吗？ | 手动也要守安全边界 |

---

## 5. 为什么

1. **为什么模式判断只放在输出段？** 放在状态里，等于给每个状态都加一个分支，改一次要改十处，必然漏。
2. **为什么自动逻辑一个字都不改？** 因为"没改"是可以证明的（回归一致）；"只改了一点点"没法证明。
3. **为什么要定"不许切换"的条件？** 手动/自动切换是现场事故高发点，规则不写清，操作工就会在带载时切。

---

## 6. 收尾

> **"加功能不是加代码，是加一张表：每种模式下每个输出该是什么。表里没有空格的，才叫设计。"**
